### What is switched off

- **T7 routing.** T7 is `expt_b8`'s: six statements by `product_id`/`inventory_id`, each sent to every `inventory` shard. There is no `product_merchant_map`, and the coordinator is not registered in Citus's metadata (it was only needed for that reference table).
- **T1 delegated.** T1 is `expt_b8`'s multi-statement T1 inside `BEGIN`/`COMMIT`, sent statement by statement through the coordinator; each item's inventory `UPDATE` keeps its own `quantity >= qty` guard. `run.sh` does not create `place_order`.

Because T5 routing and the T6 rollup are on, the original T1 also runs the `order_merchant_map` insert and then the `merchant_daily_sales` upsert (for `CURRENT_TIMESTAMP::date`, the order's day), after its final `UPDATE orders SET total_amount` and before `COMMIT`, using the same `(:order_total)::numeric(12,2)`. The original T1 never ran with these writes in the chain; they mirror steps 7 and 6 of `place_order`.

### What to look at when this is run

- **Comparability.** Same nodes as `expt_b19` (`xcnf[17-21]`), run alone: `ablation_b19/submit.sh` chains every cell with `afterany`.
- **`schema-create.log` and `explain.log`.** No errors; switched-off tables are absent.
- **`pgbench_exit_code`, aborted clients, retries and serialization failures** at every client count.
