### Prev: expt_a300 (grid base)

Cell 338 (T1 mode 2 `fn_rc`, mask 6) of the 2^4 x 3 workload-A ablation (`ablation/README.md`); every cell's factor levels are in `ablation/manifest.csv`. Generated by `ablation/generate.py` from `ablation/template/`: change the template and regenerate rather than editing this directory.

Everything not listed below is the grid's shared reference: `expt_a100`'s (formerly `expt_a3`) schema, distribution, indexes, T2, T3, T4, T8, T9 and server parameters, with `expt_a9r`'s run configuration (`--nodelist=xcnf[0-2,4,5]`, `TEAM_ID` default 4, `PGPORT` derived from `TEAM_ID`). `run.sh` also records plans outside the timed benchmark.

Enabled factors:

| `t6_rollup` (bit 2) | T6 rollup: T6 reads `merchant_daily_sales`; T1 upserts the rollup row; `run.sh` creates it with `idx_mds_period`, distributes, fills and truncates it | `expt_a102` (formerly `expt_a5`) |

| `t1_mode=fn_rc` (m=2) | T1 delegation under READ COMMITTED: as `fn`, plus `PG_ISOLATION_LEVEL` defaults to `read committed`, `place_order`'s stock check takes `FOR UPDATE OF i`, and the function sets `plan_cache_mode = force_custom_plan` | `expt_a347` (formerly `expt_a11`) |

T1's `place_order` is `expt_a347`'s with step 7 (`order_merchant_map` insert) removed from the function body. The signature, the pgbench-side statements and the rest of the body are unchanged, and the remaining steps keep the original numbering.

READ COMMITTED is only valid together with the stock lock, which only the delegated function has. Without `FOR UPDATE OF i`, two concurrent orders can both pass the stock check before either decrements, and the decrement has no stock predicate for READ COMMITTED to recheck: the second order is accepted against stock that is gone, and only `CHECK (quantity >= 0)` stops it, as an error rather than a clean rejection. The lock makes the second check wait for the first order and read its result. The full argument is in `expt_a347/optimisations.md` (formerly `expt_a11`).
