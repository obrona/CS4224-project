### Prev: expt_b300 (grid base)

Cell 339 (T1 mode 2 `fn_rr`, mask 7) of the 2^4 x 3 workload-B ablation (`ablation/README.md`, "Workload B"); every cell's factor levels are in `ablation/manifest_b.csv`. Generated by `ablation/generate.py --side b` from `ablation/template/`: change the template and regenerate rather than editing this directory.

`transactions/` and `explain/` are byte-identical to `expt_a339`'s, the workload-A cell with the same factor levels, and `run.sh` differs from `expt_a339`'s only in the node pin (`--nodelist=xcnf[17-21]`, the B-side node set: disjoint from A's and shared by every B cell), the mail user and the `WORKLOAD` default (`B`).

Everything not listed below is therefore the grid's shared reference, as on workload A: the schema, distribution, indexes, T2, T3, T4, T8, T9 and server parameters of the workload-A base design (formerly `expt_a3`, see git history), `TEAM_ID` default 4 and `PGPORT` derived from `TEAM_ID`. `run.sh` also records plans outside the timed benchmark.

Enabled factors:

| Factor | Description |
| ------ | ----------- |
| `t5_routing` (bit 1) | T5 routing: T5 looks up `order_merchant_map`; T1 inserts the map row; `run.sh` creates, distributes, fills and truncates `order_merchant_map` |
| `t6_rollup` (bit 2) | T6 rollup: T6 reads `merchant_daily_sales`; T1 upserts the rollup row; `run.sh` creates it with `idx_mds_period`, distributes, fills and truncates it |
| `t7_routing` (bit 4) | T7 routing: T7 is `expt_b7`'s: it looks up `product_merchant_map` before `BEGIN` and routes its two `UPDATE`s; `run.sh` creates, distributes, fills and truncates `product_merchant_map` |
| `t1_mode=fn_rr` (m=2) | T1 delegation under REPEATABLE READ: as `fn`, plus `PG_ISOLATION_LEVEL` defaults to `repeatable read` instead of `serializable` |

T1 is `expt_a323`'s, unchanged.

The code is cell 323's (T1 mode `fn`, the same mask) except for one line of `run.sh`: `PG_ISOLATION_LEVEL` defaults to `repeatable read` instead of `serializable`. `run.sh` writes it to every node's `default_transaction_isolation`, so it applies to every transaction of the workload, not only T1.
