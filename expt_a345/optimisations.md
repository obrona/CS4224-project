### Prev: expt_a300 (grid base)

Cell 345 (T1 mode 2 `fn_rr`, mask 13) of the 2^4 x 3 workload-A ablation (`ablation/README.md`); every cell's factor levels are in `ablation/manifest.csv`. Generated by `ablation/generate.py` from `ablation/template/`: change the template and regenerate rather than editing this directory.

Everything not listed below is the grid's shared reference: the schema, distribution, indexes, T2, T3, T4, T8, T9 and server parameters of the workload-A base design (formerly `expt_a3`, see git history), with `expt_a323`'s run configuration (`--nodelist=xcnf[0-2,4,5]`, `TEAM_ID` default 4, `PGPORT` derived from `TEAM_ID`). `run.sh` also records plans outside the timed benchmark.

Enabled factors:

| Factor | Description |
| ------ | ----------- |
| `t5_routing` (bit 1) | T5 routing: T5 looks up `order_merchant_map`; T1 inserts the map row; `run.sh` creates, distributes, fills and truncates `order_merchant_map` |
| `t7_routing` (bit 4) | T7 routing: T7 is `expt_b7`'s: it looks up `product_merchant_map` before `BEGIN` and routes its two `UPDATE`s; `run.sh` creates, distributes, fills and truncates `product_merchant_map` |
| `shards8` (bit 8) | Eight shards: `run.sh` sets `citus.shard_count` to `CITUS_SHARD_COUNT` (default 8, Citus's own default is 32) in the session that distributes every table, and records it in `config.txt` |
| `t1_mode=fn_rr` (m=2) | T1 delegation under REPEATABLE READ: as `fn`, plus `PG_ISOLATION_LEVEL` defaults to `repeatable read` instead of `serializable` |

T1's `place_order` is `expt_a323`'s with step 6 (`merchant_daily_sales` upsert) removed from the function body. The signature, the pgbench-side statements and the rest of the body are unchanged, and the remaining steps keep the original numbering.
Step 4 still has `RETURNING total_amount, created_at INTO v_order_total, v_created_at`, although only step 6 read them.

The code is cell 329's (T1 mode `fn`, the same mask) except for one line of `run.sh`: `PG_ISOLATION_LEVEL` defaults to `repeatable read` instead of `serializable`. `run.sh` writes it to every node's `default_transaction_isolation`, so it applies to every transaction of the workload, not only T1.
