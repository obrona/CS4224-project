### Prev: expt_a300 (grid base)

Cell 343 (T1 mode 2 `fn_rc`, mask 11) of the 2^4 x 3 workload-A ablation (`ablation/README.md`); every cell's factor levels are in `ablation/manifest.csv`. Generated by `ablation/generate.py` from `ablation/template/`: change the template and regenerate rather than editing this directory.

Everything not listed below is the grid's shared reference: the schema, distribution, indexes, T2, T3, T4, T8, T9 and server parameters of the workload-A base design (formerly `expt_a3`, see git history), with `expt_a323`'s run configuration (`--nodelist=xcnf[0-2,4,5]`, `TEAM_ID` default 4, `PGPORT` derived from `TEAM_ID`). `run.sh` also records plans outside the timed benchmark.

Enabled factors:

| Factor | Description |
| ------ | ----------- |
| `t5_routing` (bit 1) | T5 routing: T5 looks up `order_merchant_map`; T1 inserts the map row; `run.sh` creates, distributes, fills and truncates `order_merchant_map` |
| `t6_rollup` (bit 2) | T6 rollup: T6 reads `merchant_daily_sales`; T1 upserts the rollup row; `run.sh` creates it with `idx_mds_period`, distributes, fills and truncates it |
| `shards8` (bit 8) | Eight shards: `run.sh` sets `citus.shard_count` to `CITUS_SHARD_COUNT` (default 8, Citus's own default is 32) in the session that distributes every table, and records it in `config.txt` |
| `t1_mode=fn_rc` (m=2) | T1 delegation under READ COMMITTED: as `fn`, plus `PG_ISOLATION_LEVEL` defaults to `read committed`, `place_order`'s stock check takes `FOR UPDATE OF i`, and the function sets `plan_cache_mode = force_custom_plan` |

T1 is `expt_a347`'s, unchanged.

READ COMMITTED is only valid together with the stock lock, which only the delegated function has. Without `FOR UPDATE OF i`, two concurrent orders can both pass the stock check before either decrements, and the decrement has no stock predicate for READ COMMITTED to recheck: the second order is accepted against stock that is gone, and only `CHECK (quantity >= 0)` stops it, as an error rather than a clean rejection. The lock makes the second check wait for the first order and read its result. The full argument is in `expt_a347/optimisations.md`.
